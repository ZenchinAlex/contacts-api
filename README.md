# contacts-api

Учебный API телефонной книги на FastAPI. Контакты хранятся в файле `contacts.json`.

## Возможности

| Запрос | Что делает | Коды ответа |
|---|---|---|
| `GET /contacts` | Вернуть все контакты | 200 |
| `GET /contacts/{name}` | Найти телефоны по имени | 200, 404 (контакт не найден) |
| `POST /contacts` | Добавить контакт (`name`, `phone`) | 200, 409 (такой контакт уже есть), 422 (неверные данные) |

## Как запустить

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
fastapi dev main.py
```

Сервер откроется на http://127.0.0.1:8000, документация и проверка запросов: http://127.0.0.1:8000/docs

Файл `contacts.json` создаётся сам при первом добавлении контакта.

## Чему я научился

- Принимать JSON в `POST`-запросе: описал модель `Contact` на Pydantic, FastAPI сам проверяет данные и возвращает `422`, если поля не хватает.
- Отсекать дубликаты: прохожу циклом по списку и проверяю, что совпадают и имя, и телефон (`and`); при совпадении возвращаю `409`.
- Сохранять данные в файл `contacts.json` через `json.load` и `json.dump`, чтобы контакты не пропадали при перезапуске сервера.
- Различать коды ответов: `404` (не найдено), `409` (конфликт), `422` (данные не прошли проверку).
- Проверять API через `/docs` (Swagger): «Try it out → Execute», без отдельных программ.
- Находить ошибки по шагам: факт → гипотеза → проверка. Например, нашёл, что `if` стоял внутри цикла из-за отступа.
